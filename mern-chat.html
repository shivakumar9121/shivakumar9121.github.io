CASE STUDY 03 / FULL-STACK DEVELOPMENT

A conversation, end to end.

MERN Real-Time Chat Application

React account screens, persistent conversations and live message events with Socket.IO.

JavaScriptReactNode.jsExpressMongoDBSocket.IO

THE PROBLEM

A chat application needs to coordinate identity, conversation history and live updates across the browser, HTTP server, database and socket connection.

I built a MERN messaging application with registration, login, conversation and message screens. Express handles HTTP requests, MongoDB stores conversation data, and Socket.IO delivers message and presence events.

ARCHITECTURE

  1. 01React screens
  2. 02Express HTTP
  3. 03JWT middleware
  4. 04MongoDB
  5. 05Socket.IO events

IMPLEMENTATION

HTTP for persisted state

Authentication and message routes use Express controllers and Mongoose models. JWT cookies protect the HTTP routes; bcrypt hashes passwords.

Events for live updates

Socket.IO complements the persisted conversation flow with message events and online-user presence. The frontend connects these events to conversation state.

Separate browser concerns

React pages and hooks divide registration, login, user lookup, message retrieval and message sending. A Vite proxy forwards development HTTP requests to the backend.

RESULT & NEXT STEPS

What the project demonstrates

The implementation includes the frontend, backend, data models and screenshots of a running local conversation. The repository provides setup steps and an existing Render link, whose full authenticated messaging flow has not been independently validated.

Engineering considerations

The HTTP API and socket endpoint must target the same backend. The current socket client still points to an older hosted endpoint and the server accepts a supplied user ID for presence.

Align the socket endpoint, verify identity on the socket server and add reconnect, authorization and input-validation tests before a production release.

Review backend/controllers, backend/models, backend/socket and frontend/src for the implementation. The README documents current setup and deployment limitations.
