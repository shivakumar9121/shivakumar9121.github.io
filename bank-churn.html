Bank Customer Churn — ML & Explainability Dashboard

Five classifiers, SHAP explanations and an interface for exploring customer churn risk.

PythonPandasscikit-learnXGBoostSHAPStreamlit

THE PROBLEM

A churn-risk estimate is more useful when the analyst can inspect the data, compare models and understand which features contribute to the model’s output.

During my Data Analyst internship at Unified Mentor, I prepared customer data, engineered features and compared five classifiers. A Streamlit dashboard brings risk estimates, score distributions, explanations and what-if exploration into one interface.

ARCHITECTURE

  1. 01Customer CSV
  2. 02Prepare features
  3. 03Compare models
  4. 04Save artifacts
  5. 05Streamlit + SHAP

IMPLEMENTATION

Reusable preparation

Pandas and NumPy support cleaning, encoding and feature construction. Balance-to-salary ratio, product density, engagement-product score and age-tenure interaction add derived inputs.

Model comparison

The training workflow uses a stratified 80/20 split. Numeric scaling is fitted on the training partition. Logistic regression, decision tree, random forest, gradient boosting and XGBoost are compared with classification metrics.

Explanations and exploration

Saved model artifacts, feature names and scaling metadata feed the app. SHAP analysis provides a feature-contribution view, while what-if controls let an analyst explore the model’s sensitivity to inputs.

RESULT & NEXT STEPS

What the project demonstrates

The repository contains the dashboard, training scripts, model artifacts, evaluation data and explanation figures. The result demonstrates an implemented analytical workflow; no customer-retention uplift or business adoption is claimed.

Engineering considerations

Preprocessing must remain consistent between model training and the dashboard. Model comparison also needs an evaluation design that separates selecting a model from assessing its final performance.

The same test partition currently informs model selection. A separate validation/final-test protocol, cross-validation and calibration checks would strengthen evaluation. What-if predictions should not be interpreted as causal effects.
